# 大脑图加载性能实施计划

**目标：** 保留右向脑图、全部展开及历史折叠状态，使创建、绘制、布局和连接线更新持续让出主线程。用户已批准前述分批方案，并要求实际浏览器自测后交付。

**架构：** 在现有编辑器内增加可取消的分片调度，复用 KityMinder 的渲染器及布局计算；同步 API 保持兼容。初始预算为 6 毫秒。数据库、WebSocket 协议、执行结果值均不变。

**约束：** 当前 `codex/execution-floating-panels-demo` 分支；不修改 next-test-case。按后续继续指令采用全量数据、全量布局、全量 SVG 创建及屏外分组跳过绘制：不按区域请求数据，不减少节点，不改变既有交互或后端逻辑。诊断产物、Chrome 配置及日志均位于本项目目录。

## 实施与验收

- [ ] 创建真实 Chrome 回归脚本：通过项目内 puppeteer-core 启动独立 Chrome，加载真实 kity、脑图引擎及导入函数；监测定时器最长延迟、长任务、实际节点数、内容/状态与坐标。先在原代码验证会报告长时间阻塞。
- [ ] 新增 `progressiveRender.js`：分片渲染、两轮自底向上布局及自顶向下矩阵/连线应用；每轮检查取消，不在结束时再次同步刷新整图。
- [ ] 修改 `largeMindMap.js`：共用时间预算调度，支持取消/替换加载；成功后统一发完成事件，错误与取消释放状态。
- [ ] 修改文字渲染：把坐标设置放在读取尺寸前的写入阶段，避免逐行交错写入与测量；不改变字体和图标。
- [ ] 编辑器卸载、Socket 重连接入取消；完成后重置撤销基准，避免部分树成为撤销快照；保留只读和锁定状态。
- [ ] 单元验证：完整节点、已存结果、折叠状态、取消/替换以及完成事件顺序。运行现有执行结果和编辑器回归。
- [ ] Chrome 实测：小图比对同步与异步坐标/尺寸；逐步扩大到 5 万节点，监测总耗时和最长响应间隔；检查编辑文本、选中、结果图标、导出和折叠。
- [ ] 生产构建、OCR 完整变更审查、修复及复测；提交中文 Git commit 并按 GitHub 包装脚本推送。停止测试 Chrome 和测试服务器；交付逐项结果和已知限制。

## 风险与恢复

异步任务与远端更新可能交错：替换导入必须取消前一代任务，完成回调不能覆盖新任务状态；卸载不能缓存半棵树。文字尺寸依赖浏览器 SVG，不能将完整绘制移入 Worker。单节点下子节点极多的布局需观察最慢批次。全量 SVG 内存压力仍需实测，超过验收条件不得报告通过。

回滚只涉及前端代码和生产资源，不更改数据库。浏览器测试使用隔离数据，禁止修改用户真实结果。
